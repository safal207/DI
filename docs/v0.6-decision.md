# DI v0.6 Decision

Decision: **NO-GO / DEFERRED**

Date: 2026-08-28

## Question

Does the new ambiguous-payment sandbox evidence justify a new DI architecture layer or conformance profile?

## Evidence reviewed

```text
Published checkpoint: v0.5-draft
Sandbox scenario: commit → lost acknowledgement → authoritative lookup
Stored effects: 1
Duplicate effects: 0
Valid trace: PASS
Unsafe mutations rejected: 6 / 6
```

Evidence pack:

```text
evidence/ambiguous-payment-sandbox/
```

## Finding

The deterministic case is representable by the existing `ambiguous-commit-v0.5` profile.

The current model correctly preserves:

- one logical operation;
- one stable effect key;
- local `unknown` after transport ambiguity;
- authoritative commit resolution;
- one committed effect identity;
- `ACCEPT_EXISTING_EFFECT` as the next action;
- observed `PAYMENT_COMMITTED` state.

The validator also rejects the tested unsafe alternatives.

Therefore the evidence does **not** reveal a missing architecture seam.

## Decision

```text
NO v0.6 now
```

Continue with:

- external sandbox and test-mode evidence;
- adapters;
- usability;
- stable error codes;
- benchmark cases;
- paid pilot validation;
- bug and security fixes within the existing profile ladder.

Do not add:

- a new profile number;
- a new normative layer;
- new semantics merely to make the project look more advanced.

## Why this is the stronger decision

A new version would add complexity without solving an observed failure.

The present evidence supports the current architecture rather than contradicting it.

```text
new evidence fits v0.5
→ strengthen v0.5 adoption
→ do not manufacture v0.6
```

## Reopen conditions

Reopen the v0.6 decision only when all six architecture-freeze conditions are satisfied:

1. a reproducible external trace exists;
2. a minimal counterexample is isolated;
3. the current profile either accepts an unsafe trace or cannot represent a required integrity property;
4. a mutation test demonstrates the proposed rule;
5. the claim boundary is explicit;
6. project-boundary review confirms the change belongs in DI.

Examples that might justify reopening:

- two authoritative systems of record disagree and v0.5 cannot model resolution authority;
- one logical operation legitimately spans several atomic effects and current identity semantics are too strict;
- evidence arrives out of order across layers and current freshness/generation rules permit an unsafe conclusion;
- a real provider trace passes while still allowing a duplicate effect;
- the required integrity property belongs between two existing records but cannot be expressed without silent scope drift.

These are hypotheses, not current findings.

## Claim boundary

This decision says:

> The current deterministic evidence does not justify expanding DI beyond v0.5.

It does not say:

> v0.5 is complete for every external system or no future gap will be found.

## Next decision target

The next architecture review occurs after one of these:

- a sanitized external provider test-mode trace;
- a paid client pilot;
- a public incident mapped into the current model;
- a reproducible counterexample submitted by a contributor.

Until then:

> More evidence, fewer speculative layers.
