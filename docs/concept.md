# DI Concept

Doability Intelligence (DI) is the discipline of understanding what can and cannot be done before a system commits to a decision or action.

DI exists because intelligent systems often confuse:

- request with intent,
- capability with permission,
- possibility with feasibility,
- feasibility with responsibility,
- action with commitment.

DI introduces a boundary between understanding and commitment.

## Central Question

> What must be understood before this action can be promised, planned, or executed?

## Core Distinctions

| Concept | Meaning |
|---|---|
| Request | The raw instruction, signal, or demand received by the system |
| Intent | The clarified meaning behind the request |
| Capability | The system can technically perform the action |
| Limitation | The system cannot perform it fully, safely, or validly |
| Constraint | A rule, boundary, policy, or condition affects the action |
| Feasibility | The action can be validly attempted under known conditions |
| Commitment | The system has moved from assessment into decision or execution |

## DI Boundary

DI happens before commitment.

Once a decision is made, DRP records it.

DI should clarify limits without becoming the decision log itself.
