## LinkedIn / Longer Post

```text
I’m opening DI — Doability Intelligence — for contributors.

DI is a small open-source protocol/spec for mapping what can and cannot be done before decisions become commitments.

Core architecture:

DIF → clarify intent
DI  → clarify limits
DRP → commit decision

Adjacent protocol:

TIP → Transition Intelligence Protocol: studies transitions between states, including readiness, ambiguity, and safe movement from one state to another.

DI asks questions such as:

- What is technically possible?
- What is constrained?
- What is blocked?
- What is unknown?
- What requires human review?
- What should not be promised yet?

The repository already includes:

- RFC-0001 draft
- JSON schemas
- practical examples
- valid and invalid fixtures
- minimal dependency-free validator
- GitHub Actions CI
- contributor guide
- roadmap
- good first issues

I’m looking for contributors interested in:

- AI safety
- agent governance
- QA and validation
- decision integrity
- transition intelligence
- protocol design
- human-in-the-loop systems
- responsible AI workflows

Good first contributions are intentionally small:

1. Add one real-world DI example.
2. Add one invalid schema fixture.
3. Clarify one RFC open question.

Main repo:
https://github.com/safal207/DI

Related projects:
https://github.com/safal207/DIF
https://github.com/safal207/DRP
https://github.com/safal207/transition-intelligence-protocol

Good first issues:
https://github.com/safal207/DI/issues/6

https://github.com/safal207/DI/issues/8
```

## Manual Publishing Checklist

1. Open X / LinkedIn.
2. Paste the short or long post.
3. Add the DI repo link.
4. Add good first issues either in the post or first comment.
5. Add related project links only after the main DI link.
6. Pin or save the post if possible.
7. Reply to anyone who reacts with a concrete issue link.

## Reply Template for Interested Contributors

```text
Thanks for your interest.

The easiest entry point is one of these good first issues:

- Add one new DI example: https://github.com/safal207/DI/issues/6
- Add one invalid fixture: https://github.com/safal207/DI/issues/7
- Clarify one RFC question: https://github.com/safal207/DI/issues/8

The repo is intentionally small and protocol-like, so a focused PR is better than a large one.
```

## Principle

Do not ask people to “help the project” in the abstract.

Ask them to pick one small issue:

- add one example,
- add one fixture,
- clarify one RFC question.
